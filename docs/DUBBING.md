## Recording and delivery

From PLAN.md §10.1:

- Record at **WAV 48kHz mono**. Masters stay out of the repository.
- Deliver as **OGG Vorbis, mono, ~96kbps**, normalised to about **-3 dBFS**.
- Trim leading and trailing silence to under **50ms**. The game inserts its own
  90ms gap between clips in a composed line; padding inside the file fights it.
- One clip per row below, at exactly the path given. A file at any other path
  will not be found — `VoiceBank` reads the manifest and never scans the disk.

### Lines that get assembled

Customer orders are built at runtime from separate clips rather than recorded
whole (§10.3):

```
[cust_ibu_open] [num_3] [item_pisang] [cust_ibu_and] [num_1] [item_roti] [cust_ibu_close]
  "Saya mau beli"  "tiga"  "pisang"        "dan"        "satu"  "roti"      "ya"
```

So the number and item words have to sit naturally **mid-sentence**, not as
standalone words with a falling intonation. Read them as if the sentence
continues, because it does.

### Lines with several variants

A child hears these dozens of times per session. Where a line lists more than
one take, make them **genuinely different** — different wording is welcome, not
just a different reading of the same words. Identical praise every time is what
makes an app feel mechanical (§10.4).

## Checking progress

```powershell
& $env:GODOT --headless --path . res://tools/check_voice_coverage.tscn
```

Until a file exists, the game logs the voice ID and waits out the line's
duration in silence, so everything stays playable while recording is in
progress (§10.5).
